# Database Migrations

SatyaVoice uses [Alembic](https://alembic.sqlalchemy.org/en/latest/) for database migrations. This ensures that the schema can evolve safely over time, preserving the audit trail and enrolled speaker identities.

## Local Development Database

By default, local development uses SQLite. The application is configured to automatically create tables (`Base.metadata.create_all()`) on startup if the `VOICETRUST_DB_CREATE_ALL` environment variable is set to `true` (which is the default for SQLite).

This creates a disposable local database but **does not** track schema versions or run migrations. If you need to test migrations locally, disable the auto-creation and use Alembic:

```bash
export VOICETRUST_DB_CREATE_ALL=false
alembic upgrade head
```

## Production PostgreSQL

In production, the application connects to PostgreSQL. **`create_all()` is disabled by default in production.**

### Deployment Behavior

During deployment, the schema must be updated using Alembic *before* the application starts. The standard deployment workflow is:

1. Deploy new application code.
2. Run database migrations:
   ```bash
   alembic upgrade head
   ```
3. Start the application servers (Uvicorn/FastAPI).

### Alembic Commands

- **Run all pending migrations (Upgrade):**
  ```bash
  alembic upgrade head
  ```

- **Rollback one migration (Downgrade):**
  ```bash
  alembic downgrade -1
  ```
  *Note: Downgrades are not always safe (e.g., dropping a column deletes data permanently). Test downgrades locally before attempting in production.*

- **Create a new migration (Autogenerate):**
  ```bash
  alembic revision --autogenerate -m "Add new column to risk_events"
  ```
  Always review the autogenerated script in `alembic/versions/` before committing, as Alembic may not catch all intent (e.g., table renames).

## Rollback Considerations

- If a deployment fails, you may need to downgrade the database schema to the previous version before rolling back the application code.
- Ensure the `downgrade()` function in the migration script is correctly implemented. For example, downgrading a column from `nullable=True` to `nullable=False` will fail if there are existing `NULL` records.
